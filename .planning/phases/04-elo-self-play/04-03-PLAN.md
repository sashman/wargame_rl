# Elo-Based Self-Play, Wave 3 — The Mirror Sees the Whole Board

**Goal:** Let a checkpoint play the opponent seat, so checkpoints enter the rating
table and `just measure-paired ckptA ckptB` becomes a paired agent-vs-agent head-to-head
— with no retrain and no model change.

**Architecture:** Split in two so the dependency direction survives. The env half
(`SelectorOpponentPolicy`) is torch-free and seats *any* `ActionSelector`; the model
half (`NetworkOpponentPolicy`) subclasses it and registers the `"model"` key
**downward** into the lower layer's registry. A single `envs/opponent/model_policy.py`
importing `net.py` would be a DDD violation *and* a real import cycle, since `net.py`
imports `envs.wargame`.

**Spec:** [docs/self-play.md](../../../docs/self-play.md) § The mirror,
§ The egocentric invariant. Context and decisions: [04-CONTEXT.md](04-CONTEXT.md)
D-17 to D-22.

## Global Constraints

- **`tests/test_reward_golden.py` and `tests/test_observation_golden.py` must stay
  bit-identical.** Nothing on the player path changes.
- `tests/test_import_direction.py` (wave 1) must stay green — `envs/` never imports
  `model/`, `rating/` or `torch`.
- `MirroredEnv.__getattr__` **must** keep reading `self.__dict__.get("_env")`, not
  `self._env`. `copy.deepcopy` reconstructs an instance without calling `__init__`, so
  `_env` is missing during the copy and the plain form recurses until the stack ends.
  Lightning deep-copies the env in `save_hyperparameters`, so the plain version killed
  every training run on such a config at startup (PR #204). The mirror now hangs off a
  torch module, so this is *more* load-bearing than before.
- `just format && just lint` before any commit.

### Task 2: `SelectorOpponentPolicy` — any selector on either seat

**Files:**
- Create: `wargame_rl/wargame/envs/opponent/selector_policy.py`

**Interfaces:**

```python
OpponentSelector: TypeAlias = Callable[
    [WargameEnvObservation, "WargameEnv"], WargameEnvAction
]

class SelectorOpponentPolicy(OpponentPolicy):
    def __init__(
        self, env: WargameEnv, *,
        select: OpponentSelector,
        shoots: bool | None = None,
        label: str = "selector",
    ) -> None: ...
    @property
    def label(self) -> str: ...
    @property
    def mirror(self) -> WargameEnv: ...
    def select_action(
        self, opponent_models: list[WargameModel], env: WargameEnv,
        action_mask: np.ndarray | None = None,
    ) -> WargameEnvAction: ...
```

`OpponentSelector` is structurally identical to `ActionSelector`
(`evaluate.py:32`) — the third time that alias pays.

Body:

```python
observation = build_observation(self._mirror, action_registry=None)
if action_mask is not None:
    observation = dataclasses.replace(observation, action_mask=action_mask)
return self._select(observation, cast("WargameEnv", self._mirror))
```

**`action_registry=None` is deliberate and is a throughput decision.**
`_apply_opponent_action` (`wargame.py:985`) has already built a fully rules-legal mask
via `_opponent_action_mask` (`wargame.py:928`) and passes it in. Letting
`build_observation` recompute it would run `compute_unit_shooting_masks` — the
expensive LOS pass — **twice per shooting phase**. Splice, do not recompute.

`shoots` is **derived**, not declared:

```python
self.shoots = (
    env.opponent_action_handler.shooting_slice is not None
    if shoots is None else shoots
)
```

Same "cannot forget" discipline as `ScriptedBaselineOpponentPolicy`'s
`select_shooting` identity check, adapted to a policy that can emit any unmasked
action. The ordering is safe: `_opponent_action_mask` reads
`self._opponent_policy.shoots` only from `_apply_opponent_action`, which runs at
reset/step — after `__init__` has bound the attribute.

This class is **independently valuable**: it is how `rating/arena.py` seats entrant B
without YAML or the registry, and how the Phase-05 pool will seat a snapshot.

### Task 3: Split `from_env`, so a network can be sized for the other seat

`TransformerNetwork.from_env` (`net.py:648`) does `observation, _ = env.reset()` and
reads `env._action_handler` (private) at `:657`. Both are fatal here:

- `build_opponent_policy` runs at `wargame.py:296`, **inside `WargameEnv.__init__`**,
  and it is the statement that binds `self._opponent_policy`. A `from_env` call there
  hits `reset()` → `run_until_player_phase` → `_apply_opponent_action` →
  `self._opponent_policy` → `AttributeError`. Even if it did not, it would consume the
  layout RNG and shift every seeded episode.
- `env._action_handler` read through `MirroredEnv.__getattr__` falls through to the
  **real** env's handler, so a mirrored network would be sized with the *player's*
  `n_actions`. Silent on symmetric configs; wrong on asymmetric ones — exactly the
  class of bug with no shape tripwire.

**Files:**
- Modify: `wargame_rl/wargame/model/net.py`

**Interfaces:**

```python
@dataclass(frozen=True, slots=True)
class NetworkSpec:
    game_size: int
    objective_size: int
    wargame_model_size: int
    opponent_model_size: int
    terrain_size: int
    n_actions: int
    shooting_slice_start: int | None
    shooting_slice_end: int | None
    objective_padding: bool

def spec_from_observation(
    observation: WargameEnvObservation,
    action_handler: ActionHandler,
    objective_budget: int | None,
) -> NetworkSpec: ...

class TransformerNetwork(RL_Network):
    @classmethod
    def from_spec(cls, spec: NetworkSpec, is_policy: bool) -> Self: ...
    @classmethod
    def from_env(cls, env: WargameEnv, is_policy: bool) -> Self: ...
        # unchanged behaviour, now implemented as
        # from_spec(spec_from_observation(*env.reset() ...), is_policy)
```

`from_env` keeps its exact behaviour and its `print` — this is a pure extraction. Pin
that with a test asserting `from_env` and `from_spec(spec_from_observation(...))`
produce identical `state_dict` shapes.

**Interfaces:**

```python
class NetworkOpponentPolicy(SelectorOpponentPolicy):
    """params: checkpoint: str, decode_topk: int = 1,
               decode_stay: bool = False, device: str = "cpu" """
    def __init__(self, env: WargameEnv, **kwargs: object) -> None: ...

register_policy("model", NetworkOpponentPolicy)
```

Signature matches `build_opponent_policy`'s `cls(env=env, **config.params)`
(`envs/opponent/registry.py:31`) and `ScriptedBaselineOpponentPolicy.__init__`.

**Sizing, lazily.** `__init__` does `torch.load` on the checkpoint — so a missing or
malformed path fails at env construction, loudly — and stores the state dict. The
network is built on **first `select_action`**, from the mirrored observation:

```python
spec = spec_from_observation(
    observation,
    action_handler=self.mirror.player_action_handler,   # = env.opponent_action_handler
    objective_budget=self.mirror.config.objective_budget,
)
net = TransformerNetwork.from_spec(spec, is_policy=True)
net.load_state_dict(convert_state_dict(state_dict))     # STRICT
net.eval()
```

By first `select_action` the env has been reset and `place_for_episode` has run
(`wargame.py:795` precedes `run_until_player_phase` at `:800`), so the mirrored
observation is real even on a `turn_order: opponent` leg where the opponent acts during
`reset`.

**Load strictly.** `_apply_warm_start_weights` (`train.py:113`) uses `strict=False`
with no prefix rewriting, so a wrong prefix loads *nothing* and trains a random net —
a live hazard this must not copy. `convert_state_dict` (`net.py:692`) already raises on
an unknown prefix.

**Symmetry precondition, raised in `__init__`:**

```
number_of_wargame_models == number_of_opponent_models
and unit_count(player army) == unit_count(opponent army)
```

Not a nicety. `_alive_feature_index` (`net.py:301`) is
`feature_dim - n_opponents - 10`, counting backwards, and `_alive_from_features`
(`net.py:313`) falls back to **all-alive** when the index is out of range — it degrades
**silently**. On an asymmetric config a network opponent would read every model as
alive and never raise. This check is the only thing between that and a
plausible-looking wrong number, and it is removable only by the deferred size-agnostic
work.

**Free win:** `decode_joint_coherent` (`model/common/decoding.py:166`) reads only
`config`, `game_clock_state`, `opponent_models`, `player_action_handler`,
`player_models` and `rules_quantities` — every one already mirrored or genuinely
shared. So the joint constrained decode works for a network opponent unchanged. Expose
it as `decode_topk`.

**Registration flows downward.** `model/opponent/network_policy.py` calls
`register_policy` at import, so the upper layer registers into the lower layer's
registry — the standard plugin direction, preserving `model → envs`.
`model/common/factory.py::create_environment` gains one module-level
`import wargame_rl.wargame.model.opponent  # noqa: F401`; every training, evaluation
and scoring path goes through it. Direct `WargameEnv(config)` construction on a
`model`-opponent config keeps the existing `ValueError`, extended to name the fix:
`"(import wargame_rl.wargame.model.opponent, or build the env through
model.common.factory.create_environment)"`.
