### Task 2: The margin score

**Files:**
- Create: `wargame_rl/wargame/rating/__init__.py`, `wargame_rl/wargame/rating/score.py`
- Test: `tests/test_rating_score.py` (create)

**Interfaces:**

```python
DEFAULT_MARGIN_SCALE: float = 50.0  # pinned; refit only when the scenario changes


def margin_score(
    margin: NDArray[np.float64], margin_scale: float = DEFAULT_MARGIN_SCALE
) -> NDArray[np.float64]: ...


def fit_margin_scale(
    margins: NDArray[np.float64],
    wins: NDArray[np.float64],
    max_iter: int = 50,
    tol: float = 1e-10,
) -> float: ...
```

- [ ] **Step 1: Write the failing tests**

Three properties, from `docs/elo.md` § The margin belongs in the score:

- `margin_score(0.0) == 0.5` **exactly** — a VP tie is a draw with no special case.
- It saturates: per-episode `vp_margin` sd is 45–50 on 25v25, so blowouts are common
  and an unbounded score would let one layout dominate a rating.
- `margin_scale <= 0` degrades to the win indicator (1.0 above zero, 0.0 below,
  0.5 at exactly zero). This is the check that the score *generalises* Elo rather
  than replacing it.

Plus: `fit_margin_scale` recovers a planted scale from data generated with it.

- [ ] **Step 2: Implement**

`margin_score` is `1 / (1 + exp(-m / s))`, computed in a numerically stable form (use
`np.logaddexp` or clip the exponent — a margin of −400 with `s=1` must not overflow).

`fit_margin_scale` maximises `Σ [w·log s + (1−w)·log(1−s)]` over the single parameter
`1/s`. One-dimensional and concave in `1/s`, so Newton with a bisection fallback is
enough. Return `s`, not `1/s`.

- [ ] **Step 3: Run and commit**

```bash

git commit -m "feat: the victory-point margin becomes a score a rating can use"
```

### Task 3: The Bradley–Terry fit

Ratings are **fitted, not accumulated.** Sequential K-factor updates exist because
online chess cannot re-fit; here the pool is fixed and any match can be replayed, so a
sequential rule would only make a rating depend on the order games were played in —
gratuitous irreproducibility in a project whose training is otherwise bit-reproducible.

**Files:**
- Create: `wargame_rl/wargame/rating/elo.py`
- Test: `tests/test_rating_elo.py` (create)

**Interfaces:**

```python
@dataclass(frozen=True, slots=True)
class Design:
    """One row per game: pairing x leg x layout."""

    index_a: NDArray[np.intp]
    index_b: NDArray[np.intp]
    sigma_zone: NDArray[np.float64]  # +1 if A deployed in zone 1, -1 in zone 2
    sigma_turn: NDArray[np.float64]  # +1 if A moved first, -1 otherwise
    score: NDArray[np.float64]
    layout: NDArray[np.intp]  # the bootstrap resampling unit


@dataclass(frozen=True, slots=True)
class RatingFit:
    entrants: tuple[str, ...]
    ratings: NDArray[np.float64]
    h_zone: float
    h_turn: float
    n_iterations: int
    converged: bool


@dataclass(frozen=True, slots=True)
class RatingTable:
    fit: RatingFit
    lower: NDArray[np.float64]
    upper: NDArray[np.float64]
    h_zone_interval: tuple[float, float]
    h_turn_interval: tuple[float, float]
    n_bootstrap: int
    margin_scale: float


def fit_ratings(
    design: Design,
    entrants: Sequence[str],
    anchor: str = "random",
    prior_sigma: float = 400.0,
    max_iter: int = 100,
    tol: float = 1e-9,
) -> RatingFit: ...


def bootstrap_ratings(
    design: Design,
    entrants: Sequence[str],
    n_bootstrap: int = 500,
    seed: int = 0,
    alpha: float = 0.05,
    **fit_kwargs: object,
) -> RatingTable: ...


def win_probability(rating_a: float, rating_b: float) -> float: ...
```

**The model:**

```
E[s] = 1 / (1 + 10^(-(R_A - R_B + sigma_zone*h_zone + sigma_turn*h_turn) / 400))
```

`h_zone` and `h_turn` are the deployment-zone and first-turn advantages **in Elo
points**, shared across all pairs. Rather than merely cancelling an imbalance known to
exist, the fit *reports* it — a result in its own right, available before any training.

- [ ] **Step 1: Write the failing tests**

- `test_the_fit_recovers_known_ratings` — synthesise scores from planted `R`, `h_zone`,
  `h_turn`; assert recovery inside the bootstrap interval.
- `test_an_undefeated_entrant_stays_finite` — ratings are identified only up to a
  common shift, and an undefeated entrant runs to infinity without a prior.
  `squad_march_shoot` has genuinely scored a 1.00 win rate on some configs, so this is
  not hypothetical.
- `test_the_anchor_is_pinned_at_zero` — anchoring on the floor makes "zero Elo" mean
  "no better than random", the interpretation this repo already uses.
- `test_swapping_zone_and_turn_together_does_not_identify_them` — a design where the
  two axes never vary independently must fail to separate them. This is *why* the
  schedule has four legs and not two.
- `test_the_bootstrap_interval_is_wider_than_the_hessian` — on a synthetic
  fractional-score dataset. With a fractional score the Bernoulli objective is a
  *quasi*-likelihood: the point estimate is fine, but the implied variance assumes a
  Bernoulli outcome the score does not have, so the Hessian **understates** the error —
  the worst direction for a rating to be wrong in. This test is why the bootstrap is
  not a stylistic preference.
- `test_delta_elo_matches_the_linear_approximation` — `ΔR ≈ 173.7 · m̄ / s_m` near
  equality, the sanity bridge to a `measure-paired` number.

- [ ] **Step 2: Implement the fit**

Parameter vector `[R_0..R_{n-1}, h_zone, h_turn]` with the anchor's row and column
struck out. Gradient and Hessian assembled with `np.add.at`; the Hessian is `(n+2)`
square — around 12×12 here, so a dense `np.linalg.solve` is right. Newton–Raphson with
a diagonal `1/prior_sigma**2` ridge **on the `R` block only**.

Two regularisers, both necessary and both tested above: one pinned anchor, and a weak
Gaussian prior (σ ≈ 400) on `R`.

**Do not add scipy.** This is a well-behaved convex fit in ~30 lines of numpy, and
`docs/elo.md` is explicit that scipy must not become a dependency for it.

- [ ] **Step 3: Implement the bootstrap**

Resample **layouts** with replacement and re-fit; report the percentile interval.
Bootstrapping over layouts also pairs correctly: the four legs played on one layout are
one unit of evidence, not four. Take the RNG as a seed so a table reproduces.
