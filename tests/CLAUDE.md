# Testing

Applies to everything under `tests/`. General testing philosophy lives in the root `CLAUDE.md`
("Good Enough" Testing); this file covers the project-specific setup.

## Setup

- Pytest + shared fixtures in `conftest.py`; run via `just test`; coverage → `coverage.xml`
- Fixtures: `n_steps`, `env`, `experiences`, `policy_net` (a bare `TransformerNetwork`), `transformer_net`, `ppo_net`, `ppo_transformer_net`
- **`full_float32_precision` is autouse and pins `set_float32_matmul_precision("highest")` before every test.** That setting is process-wide and sticky, so one test enabling TF32 changes the arithmetic of everything after it in the same worker — which surfaced as a once-per-16-runs "flake" in `test_transformer_shooting_policy` that is actually a deterministic 25/25 failure under TF32. A test needing another mode sets it itself; the fixture only decides the starting point

## Rules

- No `@lru_cache` on fixtures — use `scope="module"`/`scope="session"` instead
- Annotate the `policy_net` fixture as `RL_Network`, not as the concrete network class
- Prefer integration tests; test through public APIs (add properties rather than accessing `_private` attrs)
- Type-annotate fixtures and test functions
- `wargame_rl/wargame/envs/interactive_demo.py` is NOT a test
- When env default config changes stepping (e.g. `skip_phases`), tests that rely on per-phase or all-phase behaviour must set config explicitly (e.g. `skip_phases=[]` in a shared `_make_env` or in the test)
- **A randomly-initialised network counts as randomness.** `TransformerNetwork.policy_from_env` seeds nothing, so a test asserting on its outputs needs `torch.manual_seed` — otherwise a failure arrives with weights nobody can reproduce
- **Before calling a test flaky, check what global state ran before it.** Process-wide torch settings survive across tests in a worker, so an intermittent *numerical* failure is more often a leak than noise. Rank hypotheses by what you can make fail on demand: thread oversubscription was the intuitive answer to the one flake seen here and gave 0 failures in 960 executions, while TF32 reproduced 25/25

**Baselines & opponents** — `test_baselines` (scripted reference policies) · `test_opponents` (opponent system) · `test_contest_and_spread_baseline` (opponent-aware allocation + de-duplicated fire; records a *refuted* hypothesis — it loses to `squad_march_shoot`, because concentration is why that bar wins) · `test_scripted_baseline_opponent` (a baseline played on the opponent side. The whole correctness question is the side-swap, so the tests are led by a *behavioural* one — the player is deployed on two of the four objectives, and `squad_march_take` playing the opponent must therefore march at the other two, which an un-mirrored policy counting its own models would not. Verified sensitive: un-swapping the enemy list fails it. Two traps it had to survive first — the episode ends on step one under the default `all_at_objectives` phase, because the player *starts* on objectives, which made a run-it-out assertion vacuous; and the opponent acts after the phase advances, so a single step tests nothing. A static scan enumerates the side-specific env attributes the baseline package reads and fails when a new one is not mirrored, since a baseline reaching for an un-swapped attribute plays for the wrong army silently. `test_an_env_carrying_this_policy_survives_a_deep_copy` is the regression for the bug that shipped: a `__getattr__` proxy reaching through `self._env` recurses forever under `copy.deepcopy`, which reconstructs without calling `__init__` — Lightning deep-copies the env in `save_hyperparameters`, so **every training run on the policy died before epoch 0** while all twelve other tests stayed green, because none of them copied an env. It steps the copy rather than only building it, so it pins playability and not constructibility)

**State I/O** — `test_snapshot` · `test_state_injection` · `test_event_stream` · `test_narrator`

**Rendering & debugging** — `test_renderer_v2` (Scene purity, control extraction, `FrameSource`, shooting, and the headless A/B against the untouched legacy renderer) · `test_debug_session` (hand-stepping a live match. The load-bearing case is `test_a_restored_env_replays_the_step_identically`: everything the debug mode is for rests on a rewind that changes nothing but the decision, so it pins reward, breakdown, per-model reward, positions, wounds and VP across a capture/step/restore/step cycle. Its fixture must actually *shoot* — shooting is skipped by default, so the weapons and `skip_phases` are load-bearing too, otherwise the RNG half goes untested. The loop tests drive `run_session` with a scripted renderer instead of a window, and their control helpers pause exactly as `DebugPresenter` does — a script that set `step_once` without pausing would exercise a combination no key can produce, and did, by silently resuming after a rewind. The inspector tests are behavioural, not pixel comparisons: the panel is *reserved* (`window_w == board + PANEL_W`, board not shrunk), clicking selects on either side, and two different selections must not draw the same column. `test_a_dead_model_earns_nothing_which_is_why_the_panel_says_so` arranges the casualty by zeroing wounds rather than shooting for one — 3v3 produced no death in 40 steps — and steps on until a *survivor* is paid, since on a step where the whole army earns zero "the dead model earned zero" proves nothing. The move-history test needs a movement-only config: with the default phases the second step is shooting, writes no records, and the test compares a step against itself. The order tests lead with `test_an_order_lands_where_the_ghost_says_not_where_the_click_was`, which authors a move, steps, and asserts the model is within 1e-9 of the drawn landing point — a ghost that lied would make every authored move a guess. Beside it: the landing point is deliberately *not* the click (the bins are coarse, and seeing how coarse is the point), a dead model is refused by name rather than by the mask, an illegal order is drawn but never applied, and the opponent wrapper is replaced rather than nested — stacking it would re-apply stale overrides for the rest of the session. The dice test steps once first so the step under test is the *shooting* one, and asserts over six seeds rather than one, since any single reroll may land on the same result by chance. The sight-shading tests are led by `test_the_shadow_is_the_engines_own_answer_and_not_the_renderers`, which walks every cell centre and asserts it is shaded exactly when `has_line_of_sight_between_points` says it is unseen — the shading is only worth believing where it contradicts intuition if it is a picture of the engine's predicate rather than of geometry the renderer projected. The rest pin what a picture cannot show: rectangles never overlap (translucent fill, so a doubled rect draws twice as dark), an empty board casts nothing, and a model in the way shades nothing — which is what the shading is a picture of) · `test_reproduce_recording` (record an episode, rebuild it from the log header's provenance, and assert the trace comes back *identical* — VP, per-step reward, both sides' positions and wounds. The fixture regenerates terrain per episode on purpose: a fixed layout would be reproduced by the config alone and the generator state would go untested. One case pins that an **unseeded** episode reproduces too, which is why provenance stores a generator state rather than a seed; one pins that provenance is header metadata and not a snapshot field, since a field on the recorded copy that a live snapshot lacks would break the replayed-equals-live invariant `test_v9_milestone_validation` asserts)

**Performance** — `test_reward_golden` (bit-identical gate: per-step reward, per-model reward, breakdown, VP and positions against recorded trajectories in `tests/data/`; use `assert_array_equal`, never `assert_allclose` — these values feed published reports, and a tolerance hides exactly the float-reassociation regression a vectorisation introduces. Regenerate only deliberately: `uv run python -m tests.test_reward_golden --regenerate`) · `test_reward_memoisation` (the two hot-path rewrites against reference copies of the code they replaced — the golden trajectories only cover the states they happen to reach) · `test_observation_golden` (the network's *input*, which `test_reward_golden` does not pin: the six observation arrays bit-identical across three configs, the batch and single conversion paths agreeing, and — anchored to env truth rather than a recorded file — that the alive column is still where `_alive_feature_index` looks. **Both gates are verified sensitive**: a one-ULP feature change and an appended per-model column each fail them on all three configs. The alive check deliberately leaves one model *wounded but alive*, because at `max_wounds: 1` `wound_ratio` is bit-identical to `alive` and an off-by-one column read is otherwise undetectable — verified, it passes without that) · `test_precision` (TF32 gated on sm_80+ and restored after, and **off unless a caller asks** — the default is pinned separately because every other test here passes `enabled` explicitly and so would miss it flipping back, which cost 8.5 vp_margin for a day in 2026-08-09; `PPOModel.forward` returns float32 under bf16 autocast, and the quantisation that makes that guard necessary — a 0.007 nat log-prob change does not survive a bf16 round trip at these magnitudes)

**Map pool** — `test_map_pool` (the third terrain mode: the three modes are mutually exclusive, a seeded reset draws the same table twice, objective count really does vary 5↔6 across the pool, a drawn map's objectives are its own areas rather than re-derived from its ruins, every draw produces one tensor shape and they collate, and the whole pool is checked *at load* — mixed counts without a budget, a budget below the pool, an unknown name, a missing directory, a map off the board. Also pins that the shipped training config holds out every fifth table, since training on all 45 would silently consume the evaluation set)

**Rating & seats** — `test_rating_score` · `test_rating_elo` (the Bradley-Terry fit on synthetic designs: planted ratings and both advantage terms are recovered, an undefeated entrant stays finite, and a schedule varying zone and turn *together* is **refused** rather than handed a fabricated split. `test_the_layout_bootstrap_is_wider_than_resampling_rows` bootstraps the same games twice, grouped and ungrouped, because the reason `docs/elo.md` gives for the bootstrap — that the quasi-likelihood Hessian understates the error — does not survive contact: any [0,1] score has variance at most p(1-p), so the Bernoulli assumption is conservative, and what the Hessian actually misses is dependence between rows) · `test_rating_schedule` (a leg is a config transform; the four legs share terrain and objectives; a config whose zones are left at their defaults is **refused**, since `battle_factory` derives them and swapping two `None`s is a silent no-op that would have `h_zone` fitted from noise) · `test_rating_arena` (a leg's margins must equal `evaluate_selector`'s on the same seeds, so the arena cannot drift into a second scoring loop) · `test_rating_ledger` (`test_all_four_leg_configs_fingerprint_identically` is the load-bearing one: `docs/elo.md`'s literal instruction would put the four legs of one pairing into four different ledgers) · `test_swap_invariance` (the mirrored observation equals the other seat's tensor for tensor — the guard that survives every shape tripwire being removed, since the static scan in `test_scripted_baseline_opponent` catches only new reads of *known* side-specific names. It needed three corrections before it meant anything, each of which left it passing and vacuous: seeding both envs alike gives two different boards because each army fills its own zone, the game tensor carries shared round/phase/score state, and objective distances are cached on the models. `test_the_comparison_would_notice_an_unmirrored_side` is the sensitivity control) · `test_model_opponent_policy` (a checkpoint on the opponent seat: it must draw **nothing** from the layout RNG, survive `deepcopy`, refuse unequal armies — `_alive_from_features` falls back to *all alive* out of range, so they degrade silently — and reject an unknown state-dict prefix rather than loading nothing) · `test_action_selector_resolution` (one resolver for a baseline name or a `.ckpt`; asserts in a **subprocess** that resolving a baseline imports no torch, which `debug.py` depends on) · `test_import_direction` (AST-walked: `envs/` imports neither `model/`, `rating/` nor torch — a real cycle, since `net.py` imports `envs.wargame` — and the rating mathematics imports nothing from `wargame_rl` at all)

**Evaluation** — `test_measure_maps` (final evaluation swaps `terrain` onto the golden scenario; the guarded failure is silent — a surviving `random_terrain` regenerates a layout and discards the map, so the run scores the training distribution while printing a map's name)

**Coherency** — `test_coherency` (the predicate, as pure geometry: a chain at exactly 2" passes, a six-model chain at 2" breaches the 9" spread, and — the case the rule's third clause exists for — **two pairs 5" apart satisfy both stated conditions and are still not a unit**, because the chain graph has two components. Also that blame lands on the straggler rather than the body it left, that dead models leave their unit so attrition cannot cascade, and that distances are base to base — the same pair is coherent with 32mm bases and incoherent as point models) · `test_coherent_deployment` (§ Setting up: every unit deploys in coherency across 20 seeds and both deployment zones, with the **control that default placement never does** — a vacuous pass here would be invisible otherwise — plus the byte-identical no-op when off, and the two config guards: a spread cap below the chain distance, and a `max_groups` that puts every model in its own unit where the rule holds vacuously)

**Coherency observation** — `test_coherency_observation` (the two `observe_coherency` columns and the corpse fix: the spread column separates a 5-model chain's ends from its middle where the nearest-neighbour column is identical for both; the component column reports 0.6/0.4 across a split unit so a model can tell which side of the break it is on; the spread clips at the cap so one stranded model cannot dominate; dead models report *compliant* values rather than violations, since the row is masked anyway and a violation there would be a standing penalty on every corpse. Plus the `_alive_feature_index` trap re-checked with the new columns on, anchored to env truth with one model genuinely dead — and asserting the model really is dead first, since `policy_from_env` resets the env and would otherwise revive it and make the test vacuous)

**Coherency enforcement** — `test_coherency_enforcement` (the end-of-move revert, on hand-placed geometry rather than on whether a policy happened to break formation. Both modes on the *same* move — `revert_unit` cancels all three models, `revert_model` returns only the straggler, **on a geometry where sending the straggler home actually leaves the unit coherent**; the original test used one where it did not, so it pinned the defect rather than the rule, and `is_coherent` now asserts the contract the revert count cannot. The escalation case is its regression: where a local revert leaves the unit spanning 18.5 against a 9 cap, `revert_model` widens to the whole unit. A unit already broken before it moved goes back to its start and stops there, still incoherent, rather than looping — plus the case that makes the modes coincide: a straggler far enough to breach the **spread** cap puts every model in the unit in breach, because that condition is collective, and this is why the modes tie on the bar and differ by 50 vp on `split_evenly`. Also that a model with no `previous_location` has nothing to revert, which is the casualty-broken unit the spec reserves attrition for)

**Coherency reward** — `test_unit_coherency_reward` (the `unit_coherency` calculator, the only coherency mechanism that is not a constraint. The load-bearing case is `test_the_straggler_and_its_squadmates_are_paid_apart`, which asserts the two payments *differ*: a term paying every model in a broken unit the same would satisfy every other assertion here and create no gradient at all, which is the mistake flat `objective_hold` made. Also that a lone survivor is **paid** rather than fined, since the rule makes a one-model unit coherent by definition and fining it prices a casualty the model did not cause; that units are scored independently, so one broken squad cannot fail an intact one; and both halves of the config guard — a config naming the calculator without `observe_coherency` is rejected at construction, **with the control that the same config is accepted once the flag is on**, since a guard that rejected unconditionally would pass the rejection test and make the calculator unusable) · **Coherency attrition** — `test_coherency_attrition` (§ Regaining coherency: the straggler dies and not the body — removing the lone model costs one where cutting the body would cost three, which is why the rule drops from the smallest component first; removal repeats one at a time until the unit is whole; a *connected* unit that merely overruns the spread cap loses its furthest model instead, since connectivity cannot pick a victim there; the loop is self-limiting because a one-model unit is coherent by definition, so a scattered unit never eats itself entirely; and the choice is deterministic, which the seeded env and the golden gates both require)

**Rules spec** — `test_scale_and_rules_quantities` (the inches↔units `Scale`, and that resolving at the default 1.0 reproduces the exact numbers the code used before the scale existed — that assertion is the no-op guarantee, so a failure means every baseline was measured under a different env; also pins that `RulesQuantities` holds only fields something reads, since a settable-but-inert config field is how a lever silently does nothing) · `test_rules_constants` (pins the domain against `docs/rules/constants.yaml` wherever the env claims fidelity; everywhere else the divergence is recorded in `implementation-status.md` rather than asserted, so a failure here means the code moved away from the spec, not that the spec is aspirational) · `test_no_ip_references` (denylist over tracked **and untracked** files — untracked matters, because a scratch file is exactly how a product reference gets reintroduced)
**Occlusion & cover** — `test_units_and_cover` (**models do not block sight — only terrain does**, a deliberate divergence recorded in the rules gap map, so a solid screen of enemy bases leaves the target fully visible while a ruin still hides it. The load-bearing case goes through `compute_unit_shooting_masks` — the mask the game actually builds — rather than a helper: the unit exemption that softened occlusion was threaded through a seam only the exposure tracker called, so a model *was* blocked by the squadmate in front of it on both real shooting paths, and a test asserting on the helper stayed green throughout. Cover is now terrain's alone: a ruin clipping one edge of the corridor is `COVER`, it costs one point of Ranged Skill, an unmodified 6 still hits, and at `base_radius: 0` the three rays coincide so cover cannot occur at all. Visibility is symmetric, which `firepower_ratio` depends on. `test_a_shot_into_cover_reports_the_expectation_it_was_rolled_under` is the *analytical* half, and it is an end-to-end case on purpose: `expected_damage` was written before cover and read the weapon's skill straight off the profile, so a unit test of the formula agreed with itself while every recorded shot into terrain was quoted against an open-ground expectation. The paired unit tests live in `test_shooting_resolution` — cover equals exactly one point of skill, RS 6 in cover still hits on a 6 rather than reporting 0.0, the no-cover default is **bit-identical** to the pre-cover formula so `test_observation_golden` and every checkpoint survive, and a 20k-trial Monte Carlo of `resolve_shooting` agrees with the closed form, which is the assertion that fails when the dice and the formula drift apart again)

**Continuous space** — `test_continuous_space_and_bases` (the two quantisations are gone, pinned on *distance travelled* rather than on a dtype — an integer array assigned a float truncates silently, so a dtype check alone would pass with the board still a chessboard: every movement action has a distinct outcome, a speed bin travels the same distance in every direction, and a model actually ends up off the grid. Plus bases: non-overlapping at placement, a zone too small for the army failing loudly with the numbers, no base hanging off the table, and objective range measured from the base edge)

**Config validation** — `test_config_rejects_unknown_keys` (every config model forbids extras, enumerated so a newly added model fails rather than silently swallowing typos; also pins that the legacy `size`/`width`/`height` aliases are *consumed* by the before-validator rather than left in the dict, and that free-form `params` dicts stay open)

**Cross-cutting** — `test_checkpoint_module_alias` (a moved module silently un-loads every existing checkpoint — Lightning pickles `PPO_Transformer` into `hyper_parameters`, so checkpoints carry import *paths*; verified sensitive by deleting the alias) · `test_integration` (backward compat) · `test_v9_milestone_validation` · `test_imports` · `test_interactive_demo`
